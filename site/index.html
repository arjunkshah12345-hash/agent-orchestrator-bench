Feature + orchestration benchmark / not a model leaderboard / 2026-10-19

There's no universal winner.

We tested how agent orchestrators run Claude Code, Codex and friends in parallel. On Linux, with a stub agent, Orca launched six agents in under 2 s against 11 to 12 s for Claude Squad, and used about ten times the memory. Which matters depends on your machine and workflow.

Key takeaways

What the data says

  1. 01

    Fast or light, not both

    In the stub-agent test Orca launched six agents in 1.52 to 1.90 s but peaked at 1124 to 1140 MB. Claude Squad took 11.18 to 11.89 s and peaked at 102 to 118 MB. Both verified 18/18.

  2. 02

    Orca: most validated

    The only GUI orchestrator we drove end-to-end on Linux, headless via orca serve. Highest weighted feature assessment (93) with full evidence coverage.

  3. 03

    T3 Code: deepest documented features

    Cross-provider delegate_task, an MCP for agents, PR flow and mobile. Its server booted headless in 1.01 s, but no agent session ran through it, so its 90 rests on docs and a server probe.

  4. 04

    Claude Squad: the light terminal option

    About 100 MB under load, scriptable through tmux, and sessions came back paused and resumable after we killed tmux. Weak on PR and remote features (assessed 65).

  5. 05

    Cloudroom: different model

    David Ondrej's tool runs sessions on cloud VMs. GUI launched in 3.3 s; the core needs root on a fresh VM so it was not installed. Assessed 72.0, range 62.0 to 82.0.

  6. 06

    No real-model results yet

    No Claude, Codex, Cursor or Grok CLI was logged in. A ready-to-run real-agent round is in the repo; nothing from it is reported as a result.

How the stub test works

6 parallel worktrees, one merge

Each orchestrator launches six sessions of a deterministic stub agent in isolated worktrees. The stub waits, then writes a reference solution; hidden verifiers decide pass or fail. Two tasks edit the same function on purpose, so one merge conflicts by design. This isolates what the orchestrator controls: launch, isolation, crash containment and footprint.

Raw logs for every number are in the repo under runs/.
