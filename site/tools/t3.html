Verdict

Strengths and weaknesses

Strengths

  • Event-sourced orchestrator, durable queue, restart recovery (v0.1.0)
  • delegate_task across providers, plus an MCP that lets agents manage threads
  • One-click PR with draft and stacked PRs; web and mobile

Weaknesses

  • We could not run a session here: it controls agents that are installed and authenticated, and none were
  • 2.9k open issues+PRs; v0.1.0 is days old
  • Users on X report the sidebar gets noisy at scale

Feature facts

From docs, repos and our probes

Platforms
Desktop (Electron: macOS dmg, Windows exe, Linux AppImage/deb), web app, iOS + Android app, headless server binary (linux/mac/win)
Supported agents
Claude Code, Codex, Cursor (via Cursor SDK), Grok Build, OpenCode (incl. OpenCode 2), Google Antigravity, Pi, Muse Code, any ACP Registry agent (Devin, Cline, Kimi, Droid...)
Parallelism
Threads per agent; each thread writes to its own branch; MCP tool to hand work off to a worktree; delegate_task child agents across providers
Isolation
Git branch/worktree per thread (vendor docs). Not containers.
Review, merge, PR
Inline diff review, one-button commit/push/PR with generated title/body, draft + stacked PRs
Remote, cloud, mobile
Strong: web, mobile, remote environments over authenticated RPC, Tailscale Serve flag, background service
MCP
Yes: T3 Code MCP (agents create/launch/message/wait/interrupt threads)
Cost visibility
Partial: usage chart in mobile, 'Limited' state + auto-resume when provider limits reset
Model choice
Per provider; switch provider/model mid-thread (with caveats)
Setup
Download app, or single headless binary: `t3 serve`
