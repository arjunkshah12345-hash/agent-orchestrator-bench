Methodology

How the scores were made, and what they are not

This is a feature and orchestration benchmark, not a model leaderboard. The ranking is a weighted feature assessment, not measured performance. Scores are editorial judgement on a 0 to 5 scale per criterion, backed by vendor docs, repos, a GitHub snapshot (2026-10-19 17:25 UTC) and hands-on probes on one Linux box. There are no real-model task results in any score: no Claude, Codex, Cursor or Grok agent CLI was logged in on the box.

Rubric

Nine criteria, 100 points of weight

KeyCriterionWeightWhat a 5 means
AAgent breadth155: 8+ agent CLIs documented, or arbitrary CLI proven
BIsolation and parallelism155: strong per-task isolation (worktree+remote, or containers) plus fan-out
CReview, merge and PR flow155: in-app diff review plus commit/PR creation and PR lifecycle
DRemote, cloud and mobile reach105: phone/web/remote runtimes or cloud execution
EOpenness and license10MIT/Apache 5, AGPL 4, source-available 3, closed 1
FMaturity and momentum15stars, release cadence/recency, vendor status, open-issue load
GLinux setup friction (measured)10from our hands-on: install, account walls, launch, footprint
HPricing and BYO model55: free, bring your own subscription
IDocs and transparency5docs site, architecture docs, honest status notes

Score = sum(weight x criterion score) / 100 x 20. A criterion with no evidence is unranked (shown as n/r). Each tool gets a range: the minimum treats unranked criteria as 0, the maximum as 5. The point score is the midpoint of that range; read it together with the range and the doc coverage, hands-on validation and measured-results columns.

Box

Test environment

Machine
Linux x86_64, 8 vCPU, 16 GB, no Docker.
Accounts
No authenticated agent CLIs. We did not buy credits or sign up for anything.
Fixture
A small Python repo with 6 tasks: bug fix, feature, refactor, test-writing checked against seeded mutants, and two deliberately conflicting edits (t5a, t5b). Hidden verifiers decide pass or fail.
Verifier self-test
All verifiers fail on the base repo, all pass on reference solutions, and t5a + t5b really conflict.

Limitations

What we could not test

  • No real-model task success. No Claude, Codex, Cursor or Grok CLI was logged in. The only key was a Groq free tier (7 to 8k tokens per minute) and one opencode request was 7.3 to 8.6k tokens. 0 of 9 attempts passed (3 rate-limit, 153 too-large and 3 tool-schema errors in the logs). Those attempts are shown below for transparency and are not used in any score.
  • T3 Code and Synara sessions. Both orchestrate agent CLIs that must be installed and authenticated; none were.
  • Cloudroom core. Its installer needs root and systemd on a fresh Ubuntu 24.04 VM, which we did not do on a shared box.
  • Closed or macOS-only tools (Conductor and others) were scored from docs and secondary sources only.
  • Judgement. Criterion scores are one reviewer's reading of the evidence. Use the sensitivity table, the score range and the coverage columns to see how much a ranking depends on it.
  • Snapshot. Stars, releases and pricing are as of 2026-10-19 and several tools ship daily.
